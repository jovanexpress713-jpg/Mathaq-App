# خطة التنفيذ — تحسين واجهة مذاق

## القيود العامة
- العمل على الفرع `improve/premium-storefront-ui` وعدم تعديل main مباشرة.
- لا تغيير لسلوك الأعمال أو API أو البيانات.
- لا إدخال بيانات تجريبية أو أرقام اتصال افتراضية جديدة.
- كل تغيير واجهة يجب أن يحافظ على RTL واستجابة الهاتف.

## المهام
1. **تأسيس فحص الواجهة**
   - افحص إعدادات المشروع بحثاً عن test runner موجود.
   - إن لم يوجد، لا تضف إطار اختبار ثقيلاً لمجرد الواجهة؛ وثّق غياب اختبارات الواجهة واستخدم lint/build المتاح للتحقق.
   - المتوقع: معرفة أوامر الفحص الحقيقية دون ادعاء اختبار غير موجود.

2. **تحسين الإطار العام والتنقل**
   - ضبط ارتفاع/مساحة المحتوى لتفادي تداخل شريط التنقل الثابت مع آخر المحتوى.
   - تحسين مظهر شريط التنقل النشط والتركيز ولوحة المفاتيح.
   - المتوقع: لا يتداخل الشريط مع المحتوى، وتبقى جميع الوجهات قابلة للوصول.

3. **تحسين بطاقة المنتج والرأس**
   - إضافة معالجة للصورة المفقودة/المكسورة دون إضافة منتجات وهمية.
   - تحسين المقروئية، مناطق اللمس، حالات hover/focus، والاتساق.
   - المتوقع: بطاقة واضحة على شاشة الهاتف وسطح المكتب، وزر الإضافة لا يفعّل فتح التفاصيل.

4. **اللمسات العامة**
   - تحسين التمرير، التحديد، الحركات وتقليل الحركة عند تفضيل النظام.
   - المتوقع: مظهر متناسق وحركة غير مزعجة.

5. **التحقق**
   - تشغيل `npm run lint` و`npm run build` إن أمكن عبر بيئة بناء متاحة.
   - مراجعة التغييرات ومقارنة الملفات بعد الكتابة.
   - عدم ادعاء أن APK بُني أو أن الواجهة اختُبرت بصرياً إن لم يحدث ذلك.
